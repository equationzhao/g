## 候选目标与验收

通过开发用命令在固定工作目录执行 `-1` 和 `--json`。一次请求按输入顺序扫描各根，两种输出读取同一组原始条目。验收覆盖空目录、重复根、显式文件、含控制字符的名称、部分失败、写出失败和同进程连续运行。

## 基线与交付边界

现有入口经 `main.preprocessArgs`、`cli.G.Run` 进入 `internal/cli`，`display.JsonPrinter.Print` 从展示字段取字符串，为每批条目分别编码。根 CLI 与配置迁移属于后续任务。1.0 机器输出仅保留 JSON，并直接切换格式。首条实现链路待定。JSON 字段契约已确认，见[字段字典](json-fields.md)，默认输出与验收样例见 [C05](behavior-contract.md#c05--json)。长列表、递归、筛选排序迁移和配置按路线图后续切片处理。

## 候选实现与验证计划

1. 将开发命令的参数转换为本次调用持有的请求，传入工作目录和输出流。
2. 按输入根获取文件身份或枚举一层目录，保存名称、类型与根编号。
3. 使用同一结果生成逐行名称或单个 JSON 文档。读取失败保留成功结果，写入失败返回给入口。
4. 用临时目录运行真实二进制，分别检查 stdout、stderr 和退出码。以失败 writer 和同进程两次调用补足进程外观察不到的情况。
