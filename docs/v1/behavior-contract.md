# g 1.0 行为契约（草稿）

状态：实现目标提案。日期：2026-11-23。对应 [功能范围](feature-scope.md) 与 [路线图](roadmap.md)。

本文件描述推荐的新行为，不是当前版本的使用手册。示例参数和 JSON 字段在相应决策冻结后才成为正式接口。已确认的功能取舍见[功能表](feature-scope.md#已确认的产品约束)。

## 如何使用本文件

1. 每个实现任务引用关联的 `Cxx` 契约与 `Fxx` 功能 ID。
2. 对推荐行为的接受或调整在任务/PR 中记录。已确定部分可以直接推进，不必等待所有未决项一次决定。
3. 对功能删除、公开接口破坏和默认行为改变，先明确范围归属与迁移方式，不能将“草稿”当作已有授权。
4. 参数拼写只是边界表示；内核只消费规范化后的 Request，不读取 CLI context。

## C01 — 调用、参数与路径

关联：F01、F17、F18。

**2026-11-24 已确认。** 普通列表无路径参数时列当前目录。文件列自身，目录列直接子项，`-d` 列目录自身。多个输入根按命令行顺序处理。默认隐藏隐藏项，显式指定 `--git-ignore` 才应用 Git 忽略规则。点名的根路径优先于这两项可见性规则；列出其子项时正常应用规则。目录符号链接的跟随策略见 D08。

- 保留 `g [options] [paths...]`。无路径且未启用 stdin 时，读取一次捕获的工作目录。
- 参数与路径可交错；`--` 后的内容全部作为路径，不再识别 flag。
- `g config` 继续表示名为 `config` 的路径。管理操作建议使用明确选项，如 `--config-check`、`--config-show`、`--completion`，避免抢占路径名。
- 读取入口时捕获 `cwd`；后续路径运算不得通过改变进程工作目录实现。
- 内核分别保留原始输入、操作路径、展示路径。符号链接解析不能覆盖原始条目身份。
- 默认不去重重复输入路径；每个输入根拥有独立 `root_id`。是否显式增加去重能力不属于最小范围。
- 现有短选项、旧 alias、多字符单横杠写法逐项列出迁移映射；采用解析库不自动决定兼容策略。

验收：无参数、两个目录、文件与目录混合、路径与 flags 混排、`g -- --no-config`、带空格的路径、重复根输入。

### 选项组合校验

参数互斥规则集中声明，由同一校验入口判定并生成诊断。规则引用选项代表的行为或特定取值，同时保留输入来源及原始拼写。`-T`、`--tree`、`--format=tree` 都选择树形模式；`--format=json` 选择 JSON 输出。校验在处理别名、配置优先级和显式关闭之后、扫描文件之前执行。同一命令行显式选择的互斥行为应保留到校验阶段。

| 规则 | 示例 | 验收 |
| --- | --- | --- |
| 互斥组（三选一） | 只列根自身 `-d`、分组递归 `-R`、树形展示 `-T` | `-d -R`、`-d --format=tree`、`-R -T` 均报冲突，顺序任意；`-T --format=tree` 是同一选择；`-R --format=json` 可以组合 |
| 需要满足至少一个前置条件 | 显式指定 `--depth` 需要启用分组递归或树形模式 | `--depth 0` 单独使用报缺少前置条件；`--depth 0 --tree` 合法 |

参数错误写入 stderr，退出码为 2。互斥提示列出实际选项并指导保留其中一个，例如 `choose only one of: -R, --format=tree`。前置条件提示列出可用入口，例如 `--depth requires one of: --recurse, --tree`。

## C02 — 配置合并与显式覆盖

关联：F16、F24。

2026-11-24 确认 `g.yaml` 覆盖全部 1.0 CLI 运行选项和输入路径，包括筛选条件、递归深度和数量限制。CLI 与配置共用选项语义；键名、嵌套方式和合并示例见 [YAML 字段提案](yaml-config.md)。

推荐优先级：`built-in defaults < user config < explicit CLI`。

- 配置为有版本的 typed 数据结构；保留哪些值被显式设置，允许 `false`、`0`、空列表覆盖默认。
- 字段列表建议整体替换；排序列表建议整体替换；需要累加的过滤项在字段说明中明确，不能由解析器偶然行为决定。
- 同一标量多次显式设置，推荐最后一次生效。互不兼容的输出编码同时请求则报告参数错误。
- `-l` 等便利选项提供明确的基础字段/布局；显式 `--fields` 覆盖其字段集合。顺序和覆盖行为要有测试。
- `--no-config` 跳过用户配置；常规读取配置不会创建目录或写文件。
- 默认配置文件不存在不报错；用户显式指定的配置不存在、格式错误、未知字段均提供具体诊断。
- 旧 `Args:` 在一个迁移适配器中转成新选项；无法映射的项被报告，不能静默丢弃。
- 环境变量只支持明确列出的约定。终端的 `auto` 行为由最后的能力解析决定；显式 CLI 覆盖环境的规则须写入字段说明。
- 配置不含 `presets`、`profiles`、命名场景、目录自动匹配规则或等价设计。

**用户配置与主题（写法提案）。** 1.0 保留自定义主题。配置文件沿用用户配置目录里的 `g.yaml`。文件缺省或仅含 `version: 1` 时使用全部内置默认值。以下示例只改变图标开关、长列表默认列和主题文件：

```yaml
version: 1
icons: true
long:
  fields: [mode, size, mtime, name]
theme: themes/local.yaml
```

主配置顶层放全局选项，特定布局的偏好放在对应键下。`long.fields` 仅在选用长列表时生效，裸跑 `g` 仍按 stdout 决定布局；显式 `--fields` 按 C04 决定布局和投影。`theme` 的相对路径以 `g.yaml` 所在目录为基准，CLI 的 `--theme PATH` 以调用目录为基准并覆盖配置中的主题选择。

主题文件使用 YAML。以 `themes/local.yaml` 为例，目录名用蓝色，Go 文件用青色，README 名称加粗：

```yaml
kind:
  directory: {color: blue}
extension:
  go: {color: cyan}
name:
  README.md: {bold: true}
```

先以同结构的内置主题为底，按属性合入用户主题。在文件名渲染时，依次应用类型、扩展名和精确文件名规则，更具体的规则覆盖同名属性。遗漏属性继承已有值，`bold: false` 可取消加粗，`icon: ""` 可清除图标。主题里的图标只在图标开关开启时显示。主配置与主题的字段、类型、选择器及样式优先级见 [YAML 字段提案](yaml-config.md)。旧主题转换独立交付；`g` 的主题加载器只读取新的主题格式。

验收：显式关闭配置中启用的值、空字段列表的校验、重复选项、未知配置项、缺省文件与显式文件的差异、旧配置迁移结果。

## C03 — 终端与非终端的默认输出

**`--format` 取值（2026-11-24 已确认）。** 1.0 仅接受 `grid`、`lines`、`long`、`tree`、`json` 五个小写值，逐字匹配。其他取值均报参数错误。`-1`、`-l`、`-T` / `--tree`、`--json` 作为独立选项，分别等价于 `--format=lines`、`--format=long`、`--format=tree`、`--format=json`。例如 `g -1` 合法，`g --format=1` 报参数错误。

关联：F02、F10。普通列表保留纵向网格（grid）、单列（`-1`）和长列表（`-l`）。

| 1.0 退役布局 | 0.x 参数 | 0.x `--format` 取值 |
| --- | --- | --- |
| across | `-x`、`--col`、`--across`、`--horizontal` | `across`、`x`、`horizontal` |
| comma | `-m`、`--comma` | `commas`、`m` |
| table | `--tb`、`--table`，以及样式选项 `--tb-style`、`--table-style` | `table`、`tb` |

2026-11-23 确认普通列表的内置默认布局由标准输出（stdout）决定。

| 调用方式 | 预期输出 |
| --- | --- |
| 在终端直接运行 `g` | 纵向网格（grid） |
| `g \| less` 或 `g > names.txt` | 逐行名称，每行一项 |
| 显式指定 `-1`、`-l` 或 `--json` | 分别输出单列、长列表或 JSON，适用于终端、管道与重定向 |

`g -l` 默认从左到右显示六列：权限、所有者、所属组、大小、修改时间（mtime）、名称。

- 大小按 1024 进位自动选择单位，例如 `512 B`、`4 KiB`、`1.5 MiB`。
- 修改时间按本次运行的时区显示，精确到分钟，格式为 `YYYY-MM-DD HH:mm`，例如 `2026-11-23 09:41`。

**统一时区（2026-11-24 确认）。** 每次调用在入口确定运行环境的时区。所有输入根、文件时间、Git 作者时间、终端与 JSON 输出、相对时间中的日历边界和时间筛选共用这个时区。各时间戳使用该时区在事件发生时的实际偏移，因此夏令时和冬令时可以有不同偏移。带偏移的输入按其表示的时刻解析，筛选和排序按实际时刻比较。

以上格式适用于长列表。JSON 字段格式见 C05，决定记录见 D06。

**终端样式默认值（2026-11-24 已确认）。** 颜色和可点击链接均为 `auto`。当 stdout 是交互终端时，各自按终端能力启用；管道或重定向默认输出纯文本。图标默认关闭，可通过命令行或用户配置开启。

其他终端展示约定：
- 颜色、图标、超链接、编号、padding 不进入 JSON 字段。
- 文件名中的控制字符在终端显示中转义；布局不能把文件名当成控制序列执行。
- 全部终端布局使用同一套宽度和截断策略，覆盖中文、emoji、组合字符与超链接。

验收：固定宽度的窄/宽窗口、无颜色模式、带控制字符的文件名、非 TTY、主题切换后机器输出不变。

## C04 — 数据与字段模型

关联：F04、F05、F10、F19–F21。

2026-11-24 确认 `--fields` 接受逗号分隔的字段名。仅指定 `--fields` 时自动使用长列表；配合 `--json` 时选择 JSON 元数据。

| 调用示例 | 验收结果 |
| --- | --- |
| `g --fields size,name` | 使用长列表，依次显示大小、名称两列 |
| `g -l --fields name,size,mtime` | 默认六列由名称、大小、修改时间三列替换，顺序与参数一致 |
| `g --json --fields size` | 条目保留 `root_id`、`path`、`name`、`kind`，另含 `size_bytes`；省略 `mtime`。特殊路径仍按 C05 携带对应的原始字节字段。JSON 对象按键名读取，键顺序可变 |
| `g --fields name,szie` | 返回参数错误并指出未知字段 `szie` |

CLI 字段 `size` 在终端按 1024 进位显示，在 JSON 中映射到字节整数 `size_bytes`。

- Entry 保存原始数据；终端 Cell/Row 单独构建。
- 字段 ID、原始类型、终端标题、采集需求、格式化函数分别定义。
- 数值不通过展示字符串回读；排序与 JSON 不依赖单位、颜色或表头文本。
- 至少区分 `not_requested`、`available`、`unsupported`、`failed`。可用零值（空文件大小 0）不能与未知混淆。
- 文件大小、分配空间和递归目录总量分别命名，不能共用一个字段却随参数改变数值语义。
- mtime、atime、ctime（元数据改变时间）、birthtime 是不同概念；缺失 birthtime 时不以 ctime 代替。
- 添加字段先声明采集需求，再接采集与输出；不得在 renderer 中补读文件。

验收：空文件大小、不可用属性、同一 Entry 的不同输出、同一字段用于显示和排序时仅采集一次。

## C05 — JSON

1.0 直接切换格式、大小使用字节整数、时间使用 RFC 3339，见 [ADR 0001](../decisions/0001-version-json-output.md)。schema v1 的 31 个条目字段及其 JSON 键、类型、适用条件和取值规则已确认，详见 [JSON 字段字典](json-fields.md)。

**默认输出**。`g --json src README.md` 产生一个 UTF-8 JSON 对象。`roots` 记录输入，`entries` 平铺所有条目，`diagnostics` 记录读取问题。例如：

```json
{
  "schema_version": 1,
  "roots": [{"id": 0, "input": "src"}, {"id": 1, "input": "README.md"}],
  "entries": [
    {"root_id": 0, "path": "src/main.go", "name": "main.go", "kind": "file", "size_bytes": 1536, "mtime": "2026-11-23T09:41:00+08:00"},
    {"root_id": 1, "path": "README.md", "name": "README.md", "kind": "file", "size_bytes": 0, "mtime": "2026-11-23T09:42:00.123+08:00"}
  ],
  "diagnostics": []
}
```

| 字段 | 类型与语义 |
| --- | --- |
| `schema_version` | 必填整数，首版为 `1`，独立于程序版本。同版本可增加可选字段；删除、改名、更改类型、单位或路径基准时升级 schema 版本。读取方按名称取值，忽略未知键。 |
| `roots` | 必填数组，按输入顺序编号，`id` 从 0 开始。`input` 保留输入拼写，无参数时为 `.`。空目录、读取失败、重复输入均各占一个根。 |
| `entries` | 必填数组，无匹配项时为 `[]`。先按根顺序分组，再按本次列表的排序输出。 |
| `root_id`、`path`、`name`、`kind` | 每条必填。`root_id` 指向 `roots[id]`。`path` 使用平台路径分隔符，基于调用时的工作目录，可直接用于同一工作目录的文件操作。绝对输入产生绝对路径，相对输入产生相对路径。显式文件输出自身，目录列出子项。`name` 是路径末段，文件系统根使用根路径。 |
| `kind` 取值 | `file`、`directory`、`symlink`、`fifo`、`socket`、`block_device`、`char_device`、`other`。按条目自身识别，断链仍为 `symlink`。 |
| `size_bytes` | 默认输出，JSON 非负整数，按文件系统返回的逻辑字节数编码。目录取目录条目自身的 stat 大小，符号链接取链接自身的 lstat 大小。读取方处理大文件时使用支持 64 位整数的解码器。 |
| `mtime` | 默认输出，按本次运行的时区编码为带偏移的 RFC 3339 字符串；保留文件系统提供的亚秒精度，最多 9 位，去掉末尾的零。符号链接取链接自身的修改时间。 |
| `diagnostics` | 必填数组，正常时为 `[]`。每条含 `root_id`、`path`、`code`、`message`。`code` 供程序判断，初始值为 `not_found`、`permission_denied`、`io_error`。`message` 为面向人的说明。字段级诊断另含 `field`，取对应 JSON 键名。 |

**缺值与部分失败**。未选择的可选元数据省略。已选择的字段自然不适用、平台无此属性或成功读取后无法识别值时，仅写 `null`。读取或采集失败时写 `null` 并附字段级诊断。可用零值直接写 `0`。若条目身份都无法取得，只写诊断。一个根出错后继续处理其他根。沿用 C13 的建议退出码：成功为 0，条目读取失败为 1，显式根不可访问或输出写入失败为 2。输出写入失败时通过 stderr 和进程状态报告，stdout 可能仅含已写入的前缀。

例如 `g --json empty missing`，其中 `empty` 是空目录，`missing` 不存在：

```json
{
  "schema_version": 1,
  "roots": [{"id": 0, "input": "empty"}, {"id": 1, "input": "missing"}],
  "entries": [],
  "diagnostics": [{"root_id": 1, "path": "missing", "code": "not_found", "message": "input path does not exist"}]
}
```

**特殊路径**。合法 UTF-8 文本直接编码，制表符、引号、换行交给 JSON 转义。在允许非 UTF-8 字节的文件系统上，`input`、`path`、`name`、`link_target` 中哪个值含非法字节，就为该键额外输出 `<键名>_b64`，使用标准带填充 Base64 编码完整原字节。对应文本中的非法序列以 `U+FFFD` 显示。诊断路径遵守同一规则。消费者需要精确还原时优先解码 `_b64`。

**迁移与验收**。旧脚本改为检查 `schema_version`、直接读取 `size_bytes` 和 `mtime`；检查 `diagnostics` 和进程状态确认结果完整。下面的查询同时适用于单根和多根，可从上面的正常示例中选出 `src/main.go`。

```sh
jq -r '.entries[] | select(.kind == "file" and .size_bytes >= 1024) | .path'
```

## C08 — 遍历、链接与输入根

关联：F01、F03、F20。链接政策见 D08。

- 路径发现、深度控制、目录剪枝、条目匹配分别实现。
- 跟随链接时按可靠的目录身份检测循环；保持原始条目路径与解析目标分开。
- 断链可展示链接本身和目标；解析目标失败不应使原始名称消失。
- 中途消失的条目、权限失败分别进入诊断。一个子目录失败不取消其他独立输入根的输出。
- `-d` 显示输入目录本身。目录大小、owner、权限等字段的来源必须与链接跟随政策一致。

验收：目录链接、文件链接、断链、循环、多根中一个失败、深度 0/1、多级路径、`-d`。

**树形入口（2026-11-24 已确认）。** `--format=tree`、`--tree`、`-T` 进入同一树形遍历和展示流程，深度、筛选、限额与跟随链接规则一致。旧值 `--format=T` 仍报参数错误。1.0 暂时移除 `--tree-style`。

**深度参数的前置条件（2026-11-24 已确认）。** 指定 `--depth N` 必须同时开启递归或树形模式。`-R`、`--recurse`、`-T`、`--tree` 和 `--format=tree` 均满足条件，参数顺序任意。单独运行 `g --depth 2 src` 报参数错误，提示 `--depth 需要配合 --recurse 或 --tree`。`-L/--follow` 只控制链接跟随。

**递归与深度取值（2026-11-24 已确认）。** `-R/--recurse` 按目录分组列出，`-T/--tree` 按树形列出。两者均支持多个输入根，按输入顺序展示，每个根独立从第 0 层计数。`--depth 0` 只列根自身，`--depth 1` 最深列到直接子项，省略深度时不限，显式负数报参数错误。例如 `g -R --depth 1 src tests` 分别列出两个根的直接子项。`-d`、`-R`、`-T` 任意两种行为组合均由[统一校验入口](#选项组合校验)报互斥。

**链接跟随（2026-11-24 已确认）。** 使用布尔开关 `-L/--follow`。点名的目录链接默认列其内容；遍历途中遇到的目录链接默认只展示，加 `-L` 才继续进入。`-d` 始终列点名条目自身。进入目标后，子项路径保留链接路径前缀，链接条目的类型、目标和自身属性遵守 C05。断链保留原始目标；沿当前祖先链检查目录身份并终止成环分支。

## C09 — 筛选与剪枝

关联：F06、F09。

- `Matches(entry)` 控制显示；`ShouldDescend(entry)` 控制遍历。
- 按扩展名或文件 MIME 筛选不能因为目录自身不匹配就停止搜索。
- tree 可以补充匹配条目的祖先作为上下文；上下文节点不伪装成命中的文件。
- 隐藏和 Git ignore 对点名路径的例外见 C01。
- 便宜的名字/路径条件先执行；只有剩余候选需要时才读取 stat、Git 或文件内容。
- 无偏移的日期时间和纯日期筛选都按本次运行的时区解释。按整日匹配时取当地当天零点（含）到次日零点（不含）。

验收：普通目录下的 `.go` 文件能被递归命中；隐藏目录开关；嵌套 ignore；筛选边界时间；无效 glob。

**筛选规则（2026-11-24 已确认）。** 保留 glob 包含/排除、扩展名包含/排除、仅目录/排除目录、仅隐藏项、排除 `~` 备份、MIME 和时间筛选。glob 匹配末段名称，glob 与扩展名区分大小写。MIME 可按完整类型或主类型匹配。时间默认取 `mtime`，before/after 分别严格小于/大于给定时刻。同类包含值取任一，不同条件取交集，命中排除项即移除。显式设置的查询条件也作用于点名的文件。无效模式或互斥条件报参数错误。

**筛选 CLI（2026-11-24 已确认）。** 支持 `--match/-M`、`--ignore/-I`、`--ext`、`--visibility=visible|all|hidden`（`-a` 选 all）、`--kind=directory|file|non-dir`、`--only-mime`、`--before`、`--after` 与已确认的 `--git-ignore`。`file` 只选普通文件；`non-dir` 选所有非目录条目，包括普通文件、符号链接及特殊文件。`--time-type` 作为共享时间选择器，数量限制单列于 C10。旧 `--no-ext` 与 `--ignore-backups` 的常见用法分别映射到 `--ignore '*.tmp'`、`--ignore '*~'`。`-a` 显示真实隐藏项，目录枚举始终跳过 `.` 和 `..`。显式输入的 `.`、`..` 照常处理。旧参数的兼容周期另见 D03。

## C10 — 排序、稳定性与数量限制

关联：F07、F03。limit 作用域见 D05。

**已确认的范围。** 1.0 退役 MIME（含父类型）与版本号排序，涵盖 `--sort` 的对应取值、`--sort-by-mime` 系列和 `--versionsort` / `--sort-by-version`。`mime` 字段、MIME 筛选与程序版本信息各自遵循对应功能的约定。

**排序接口（2026-11-24 已确认）。** 支持 `--sort=键[:方向]`、`--reverse`、`--dir-first`。方向为 `asc` 或 `desc`，省略时升序。重复 `--sort` 时按参数出现顺序比较各键。旧拼写的兼容策略见 D03。

| 排序键 | 含义 |
| --- | --- |
| `natural`、`name`、`name-no-dot` | 名称自然序、文本序、去掉一个前导点的文本序 |
| `extension`、`width` | 扩展名、文件名终端显示宽度 |
| `size`、`recursive_size` | 自身逻辑大小、目录递归总大小 |
| `mtime`、`atime`、`ctime`、`birthtime` | 修改、访问、元数据变更、创建时间 |
| `owner`、`group`、`inode` | 所有者名、组名、inode 数值 |
| `none` | 原始枚举顺序，单独使用，不带方向 |

快捷写法：`-S` = `--sort=size:desc`，`-t` = `--sort=mtime:desc`，`-X` = `--sort=extension:asc`，`-U` = `--sort=none`，`-r` = `--reverse`。

默认目录在前，同组按名称自然升序，字母忽略大小写，同值按原始名称确定顺序。显式排序跨类型比较，`--dir-first` 可叠加，反转只改变组内顺序。缺值排最后。所有排序键在比较开始前采集。

**数量限制（D05，2026-11-24 已确认）。** 公开 `-n N` 和 `--limit N`。省略或 `N=0` 表示不限；正整数表示上限；负数、非整数和缺少参数报参数错误。旧 `--limitN`、`--topN`、`--top` 的迁移见 D03。

- 每个被列出的目录先筛选直接子项，再按请求排序，取前 N 个匹配项。`-U` 按目录枚举顺序取前 N 个。普通布局和 JSON 使用同一结果。
- 各输入根独立。`g -t -n 2 src tests` 在两个目录各取最新两项；显式文件根及 `-d` 指定的根仍各自参与筛选，按输入顺序展示。
- 递归和 tree 对每个目录分别计数，N 限制展示。遍历仍按可见性、忽略和深度规则进行，达到某目录的 N 后仍可找到子目录中的匹配项。tree 只为连接已选后代补出必要的祖先，这些上下文节点不占名额。
- tree 在确实截断的目录下显示 `…` 提示，提示不占名额。普通列表与 JSON 只输出实际选中的条目。主动截断视为成功；读取失败仍按 C13 报告。


验收：同值键、组合排序、目录优先与反转、无排序、过滤后 limit、tree 截断、重复运行的确定性。

## C11 — Git

关联：F08、F09。

- 单次运行内按仓库批量收集状态，复用结果；不按每个条目启动 status 进程。
- 解析面向脚本的 porcelain 和 NUL 路径协议，正确处理 rename、空格、换行和非 ASCII 路径。
- 非 Git 仓库是正常的不适用状态；用户显式请求 Git 而可执行文件缺失、命令失败或超时，应有诊断。
- Git 调用接受 context；不会阻止取消。缓存归单次运行，不跨运行无条件复用陈旧状态。
- 工作区状态、分支、最后提交信息属于不同采集需求；普通 Git 状态不顺带逐文件查询历史。
- 子模块和 worktree 的处理范围写进支持说明。

验收：干净/修改/未跟踪/忽略/重命名、含特殊字符路径、不同仓库的多根、非仓库、缺失 Git、取消。

## C12 — 成本与资源边界

关联：F19–F23，所有基本路径。

- 先由字段、筛选、排序推导 MetadataNeeds，再执行采集。
- 默认浏览不读取文件内容、不递归统计大小、不维护持久化路径数据库。
- 同一目录枚举结果复用；不为估计数量先完整读取一次再丢弃。
- checksum 流式读取；仅最终展示需要时在 limit 后计算。多种 checksum 共享一次读取。
- MIME/charset 使用有界读取；同时请求时复用相关内容片段。
- 并发、打开文件数和缓冲区有上限。普通小目录不为每个简单操作引入调度成本。
- 特殊文件（FIFO、设备、socket）不能作为普通内容文件无条件打开。
- 缓存按条目、目录、仓库、运行划分；禁止以展示字符串作为缓存的主要数据模型。
- 不宣称所有模式都流式或所有平台都零 stat；把真实额外工作记录在基准和诊断中。

验收：统计采集器调用次数；未请求的采集器不运行；limit 后仅目标条目被哈希；大文件内存不随文件大小线性增长。

## C13 — 诊断、写出失败与退出码

关联：F01、F11、F18。

推荐继承现有代码声明的 0/1/2 分类，并补齐实际传播路径：

| 退出码 | 建议含义 | 示例 |
| --- | --- | --- |
| 0 | 请求成功；正常空结果或已定义的不适用字段不算失败 | 空目录、非仓库目录的可选 Git 字段 |
| 1 | 部分结果成功，但条目或明确请求的采集发生失败 | 子目录无权限、扫描中文件消失、某个 Git 查询失败 |
| 2 | 请求无法按契约执行 | 参数/配置错误、显式输入根不可访问、不可恢复输出失败 |

- 多个失败并存时取较严重等级；仍尽量输出独立成功根的结果。
- 机器模式 stderr 可有面向人的诊断，stdout 始终保持机器格式。结构化诊断作为 schema 中明确的数据，不夹入临时文字。
- Write/Flush 错误必须返回；不能吞掉错误后报告成功。
- Ctrl-C 和 Unix broken pipe 使用明确、符合平台习惯的停止行为；取消不打印 panic 堆栈。最终信号/退出码映射在跨平台测试中固定。
- 用户输入或正常 I/O 失败返回 error；panic 只表示实现缺陷，不用 recover 把失败伪装成功。

验收：坏参数、缺失根、部分权限失败、失败 writer、提前关闭管道、取消，分别检查 stdout/stderr/退出状态。

## C14 — 跨平台与能力一致性

关联：F04、F18、F21。

- platform 层负责系统差异；字段描述语义，不直接暴露偶然的系统结构布局。
- 平台缺少字段能力时，采集层记录 `unsupported`，JSON 按 C05 输出 `null`。
- 标准分发的功能集合明确且一致。若保留裁剪构建，版本/诊断输出列出能力。
- 对显式请求但未编译的能力返回明确诊断，不能接受 flag 后静默成功。
- 路径长度、分隔符、大小写、权限、时间属性和链接能力由实际平台 fixture 验证。
- 保留根 `go install github.com/Equationzhao/g@latest` 入口，除非另有明确的安装迁移决定。

验收：Linux/macOS/Windows 的关键黑盒用例；平台不允许的名称在该平台跳过并说明，不在仓库提交跨平台无法创建的 fixture。
